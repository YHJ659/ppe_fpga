# 검증 수치 전문

측정일 2026-08-08 · 보드 KV260(XCK26) · 비트스트림 `ppe_fpga_yoo_fix4.bit`

모든 수치는 재현 가능합니다. 판정 기준을 먼저 적고 그 다음 결과를 적었습니다.

---

## 1. 경계 텐서 — 정수 기준과 대조

`y0`/`y1`(concat 출력의 채널 0\~127)은 `conv1x1 → bn128 → split → concat` 만 거치는
**픽셀별 순수 함수**입니다. 그래서 `best.pt` 의 가중치와 캘리브레이션 값으로
정수 연산을 그대로 재현해 **정확한** 기대값을 만들 수 있습니다.

```
acc      = x_int8 @ w_int8.T                          (정수, 오차 없음)
bn_out   = acc * (S_in * W_cv1) * bn_scale + bn_shift
y        = clip(round(SiLU(bn_out) / S_cv1out), -128, 127)
out      = clip(round(y * S_cv1out / S_cat), -128, 127)
```

| 항목 | 결과 |
|---|---|
| 일치율 (1600픽셀 × 128채널) | **100.00%** |
| 불일치 바이트 / 204,800 | **0** |
| 완전일치 채널 | **128 / 128** |

수정 전과 비교하면 이렇습니다.

| | 일치율 | 완전일치 채널 | 상관계수 |
|---|---|---|---|
| 수정 전 | 8.09% | 1 / 128 | 0.512 |
| 수정 후 | **100.00%** | **128 / 128** | **1.000** |

## 2. 전체 256채널 — float 소프트웨어 모델과 대조

`y2`/`y3` 는 bottleneck(conv3x3 + bn64 + residual)을 거치며 int8 재양자화가
누적됩니다. 아래는 float 모델 기준이라 그 누적분이 차이로 나타납니다.
**`y2`/`y3` 는 `y0`/`y1` 처럼 "정확히 맞다"를 증명한 것이 아닙니다** —
그러려면 conv3x3·bn64·residual 의 정수 모의계산기를 따로 만들어야 합니다.

| 구간 | 상관계수 | 완전일치 | ±1 이내 | 평균 \|차\| |
|---|---|---|---|---|
| y0 | 0.999 | 79.4% | 99.6% | 0.21 |
| y1 | 0.999 | 81.7% | 100.0% | 0.18 |
| y2 | 0.998 | 61.5% | 98.2% | 0.41 |
| y3 | 0.998 | 38.4% | 84.8% | 0.81 |
| **전체** | **0.999** | **65.2%** | **95.6%** | **0.40** |

## 3. 연속 프레임 — 비트스트림 1회 로드

HLS IP 의 `call_counter` 는 `static` 이라 프레임마다 증가합니다. 카메라는 한 번 굽고
계속 돌리므로 **2프레임째부터가 실제 조건**입니다. 6장을 2바퀴, 총 12프레임.

| 검사 | 결과 |
|---|---|
| 전량 수신 (409,600 B) | 12 / 12 |
| 프레임당 시간 | 0.050 s (전부 동일) |
| 1바퀴째 vs 2바퀴째 | **비트 단위 동일** (다른 바이트 0) |
| y0/y1 일치율 | 12프레임 전부 100.00% |

프레임 1·7 에서 204,800바이트 중 **1바이트**가 다릅니다. 같은 입력·같은 위치로
재현됩니다. 원인을 확인했습니다 — 반올림 직전 값이 정확히 **20.500000** 으로,
경계에서 4.6e-07 떨어져 있습니다. 부동소수점 연산 순서 차이로 갈리는 동점입니다.

## 5. 원인 규명 — 어떻게 좁혔나

파라미터 메모리 주소 문제는 추측이 아니라 두 단계로 확정했습니다.

**(a) 규칙 세우기.** 입력을 전부 0 으로 넣으면 `acc = 0` 이 되어 출력이 오직
`bn_shift[c]` 하나로 결정됩니다. 즉 하드웨어가 실제로 쓴 계수를 직접 읽어내는 셈입니다.
후보를 전부 대입해 본 결과:

| 가정한 주소 규칙 | 128채널 중 재현 |
|---|---|
| `c` (정상) | 7 |
| `2c mod 256` | 7 |
| `3c mod 256` | 4 |
| **`4c mod 256`** | **128** |
| `8c mod 256` | 10 |
| `c/2`, `c/4`, `c XOR 1`, `127-c`, 바이트 뒤집기 | 3\~12 |

**(b) 다른 데이터로 검증.** 위 규칙을 **실제 이미지** 출력에 적용:

| | 전체 일치 | 완전일치 채널 | 상관계수 |
|---|---|---|---|
| 정상 주소 `c` 라면 | 8.09% | 1 / 128 | 0.512 |
| **`4c mod 256` 이라면** | **100.00%** | **128 / 128** | **1.000** |

폐기한 가설도 적어 둡니다. 어느 것도 데이터를 설명하지 못했습니다.

- 조각 경계 어긋남 — 첫 조각 안쪽도 똑같이 틀려서 폐기
- 값이 2\~4배로 부풀었다 — 상관계수가 0 이라 폐기 (배율 문제가 아니었음)
- 슬롯 오염(cv2 값을 읽음) — 대입해도 재현 안 됨
- 주소 밀림(`c±1`, `c±2`, `c±64`) — 전부 재현 안 됨
- 채널 순서 뒤섞임 — 64채널 중 55개가 제자리라 폐기
